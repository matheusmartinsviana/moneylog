# `src/modules`: negócio

Um contexto por pasta (`modules/<ctx>/`), no padrão do FE 01:

| Pasta        | Conteúdo                                                                                     | Pode importar                                   |
| ------------ | -------------------------------------------------------------------------------------------- | ----------------------------------------------- |
| `core/`      | `types`, `enums`, `interfaces` (portas), `facades` de negócio (estado da tela), `strategies` | `core` do mesmo módulo, `src/util`              |
| `infra/`     | facades de requisições (HTTP + mapeamento), `endpoints.ts`, `responses/*Response`            | `core` do mesmo módulo, `mock-data`, `src/util` |
| `mock-data/` | dados de apoio enquanto o backend não existe                                                 | —                                               |

Proibido (erro no `npm run lint:deps`): `core → app`, `core → infra`, `core → @angular/common/http`,
`infra → app`, módulo A → módulo B, ciclos. Os cálculos financeiros são do backend: o front não soma
nem subtrai valores (arquitetura §1).

## `dashboard` (T19)

Primeiro módulo; liga a página Início (`app/features/home`) à API por todas as camadas:

```
HomePage → DashboardFacade (core/facades) → DashboardGateway (core/interfaces, porta)
        → DashboardRequestsFacade (infra/facades) → mock-data (API_MOCKS = true) | GET /v1/... (Etapa 2)
```

- `core/types`: espelho de `DashboardSummary` e `Upcoming` (arquitetura §4.4) e `DashboardFailure`.
- `core/facades/dashboard.facade.ts`: estado da tela por signals (`loading`, `empty`, `error`, `data`).
  Escopo de componente (`providers` da página).
- `infra/`: `endpoints.ts`, `responses/*Response` (não vazam para `src/app`), mapeamento e
  `provideDashboard()`, chamado só no `app.config.ts` (S-31).
- `mock-data/empty-dashboard.ts`: resumo vazio (sem contas) usado na Etapa 1.
- O estado vazio vem de "existe conta ativa?" (`GET /v1/accounts?status=ACTIVE`), e não de valores
  zerados: conta com saldo zero não é "nada registrado".

## Etapa 5: `goals`, `monthly-summary`, `projections` e `exports` (a saúde financeira ficou fora do MVP: sem contrato, FE-S-157)

Cada um com `core` (tipos, porta, facades), `infra` (HTTP, mapeadores, `provideX()` chamado só no
`app.config.ts`) e `mock-data` (vazio, sem HTTP com `API_MOCKS`). **Nenhum cálculo**: percentuais (`progress`,
`savingsRate`, `percent`), saldos, reservas, `monthlyNeeded` e projeções vêm do backend como string decimal e
a tela só formata (`formatMoney`, `formatRatio` em `src/util`).

| Módulo            | Porta / facades de negócio                                                                    | Observações                                                                                                                                                               |
| ----------------- | --------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `goals`           | `GoalsGateway` · `GoalsListFacade`, `GoalFormFacade`, `GoalDetailFacade`, `GoalReserveFacade` | `Idempotency-Key` por tentativa com `IdempotencyTracker` (criar) e reuso no retry (reservar/liberar, `exhaustMap`). Liberar manda o valor **negativo** no corpo (mapper). |
| `monthly-summary` | `MonthlySummaryGateway` · `MonthlySummaryFacade`                                              | `switchMap`: trocar de mês cancela a requisição anterior.                                                                                                                 |
| `projections`     | `ProjectionsGateway` · `ProjectionsFacade`                                                    | `horizon` e `includeTrend` na query; mudar cancela a anterior. `isProjection` é sempre `true` no tipo.                                                                    |
| `exports`         | `ExportsGateway` · `ExportsFacade`                                                            | Download como `Blob` por requisição autenticada (nunca link com token); nome vindo do `Content-Disposition`; erro em `Blob` vira `Problem` (`util/api/blob-problem.ts`).  |

A entrega do arquivo ao navegador é da apresentação (`app/common/services/file-download.service.ts`).

## Etapa 6: `notes` (o vault de notas Markdown)

`core` (tipos, portas `NotesGateway` e `VaultGateway`, facades), `infra` (HTTP, mapeadores, `provideNotes()` chamado só
no `app.config.ts`) e `mock-data` (vault vazio, sem HTTP com `API_MOCKS`). **A nota nunca altera valor financeiro** e o
front não calcula nada: o corpo é **dado** (o backend não o renderiza; o front o desenha sem HTML, ver
`src/util/markdown`).

| Facade (escopo de componente) | O que faz                                                                                                                                                                                                                                                                                 |
| ----------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `NotesListFacade`             | Lista com busca (debounce de 300 ms, `switchMap`), filtro por tag e pasta, lixeira (restaurar, esvaziar), tags e a **árvore de pastas derivada dos caminhos** (o backend não tem endpoint de pastas: lê até 1.000 caminhos, ordenados).                                                   |
| `NoteEditorFacade`            | Carrega, **salva com `version`**, renomeia/move, lixeira/restaurar, vínculos e backlinks. `VERSION_CONFLICT` **nunca sobrescreve o digitado**: carrega a versão do servidor em `conflict` e o usuário escolhe (`saveOverConflict` ou `acceptRemote`). Uma escrita por vez (`exhaustMap`). |
| `NoteCreateFacade`            | Criar nota com `Idempotency-Key` por tentativa (`IdempotencyTracker`), **reutilizada** no retry depois de falha ambígua.                                                                                                                                                                  |
| `LinkedNotesFacade`           | O bloco "Notas vinculadas" das telas financeiras (`GET /v1/links`).                                                                                                                                                                                                                       |
| `VaultFacade`                 | Exportar o zip (`file$`, entregue no clique do usuário) e importar (`SKIP`/`RENAME`, tudo ou nada); 413 vira `VAULT_IMPORT_TOO_LARGE`.                                                                                                                                                    |
| `NoteSuggestFacade`           | Sugestões do autocomplete de `[[` (cada digitação cancela a anterior).                                                                                                                                                                                                                    |

Só `POST /v1/notes` declara `Idempotency-Key` no contrato; as demais escritas do vault dependem de `version` (PUT, move,
links) ou são idempotentes por natureza (trash, restore, `SKIP`).

## Redesign (ADR-011, fatia B): `reports`

`core` (tipos `IncomeExpenseSeries` e `SpendingByCategory`, porta `ReportsGateway`), `infra` (`provideReports()` chamado só no
`app.config.ts`; `ReportsDemoFacade`) e `mock-data` (fixtures determinísticas). **Os endpoints do contrato 2.6.0
(`GET /v1/reports/income-expenses` e `spending-by-category`) ainda não existem** (T181 a T185): a porta devolve
dados de **demonstração** (`isDemo = true`, a tela precisa rotulá-los) no formato que o plano descreve. Quando o backend
publicar, cria-se `ReportsRequestsFacade` (HTTP + mapeamento) e troca-se o `useExisting` em `reports.providers.ts`; os
gráficos (`app/common/components/charts`) não mudam. As fixtures fazem aritmética de centavos **só** porque simulam o
backend; o front de verdade nunca soma, divide nem compara.
